## 1. System Overview

wiki-graph-explorer is a build-time tool plus a Next.js static-export web page. Given a local
filesystem path to a Karpathy-pattern Markdown-wiki repo, it emits two static JSON assets
(`graph-data.json`, `vector-index.json`) that a `/graph` page fetches client-side and renders as
an interactive, force-directed graph with live semantic search. There is no server runtime in
production — the deployed artifact is a static site (GitHub Pages), rebuilt and redeployed
whenever the source vault changes.

## 4. API Design

No server runtime in production. The CLI surface is:

| Command | Flags | Behavior | Exit Code |
|---|---|---|---|
| `npm run build:graph -- --version` | `--version` | Prints `wiki-graph-explorer v<semver>` to stdout, exits silently | 0 |
| `npm run build:graph -- --vault <path>` | `--vault <path>` (required) | Validates `<path>` is a directory, walks the vault, writes `graph-data.json` and `vector-index.json` to output directory (default `local-build`), prints summary to stdout | 0 (success) or 1 (vault not found) |
| `npm run build:graph -- --vault <path> --out <dir>` | `--vault <path>` (required), `--out <dir>` (optional, default `local-build`) | Writes both JSON assets to the specified output directory | 0 or 1 |
| `npm run build:graph` | (no args) | Missing required `--vault` flag | 2 |
| `npm run build:graph -- --unknown` | Unknown flag | Unrecognized flag | 2 |

- `--vault` is strictly required with no fallback (no environment variable, no current directory default, no cache).
- `--out` defaults to `local-build` if omitted; used by CI/CD workflows to specify alternate output (e.g., `--out public` for deployment).
- Version is the single source of truth from `package.json#version`.

## 5. Backend Architecture

The build-time pipeline is a Node.js CLI tool that walks a vault directory, parses Markdown + YAML frontmatter, builds a graph, computes embeddings, and writes two JSON artifacts. Key modules:

| Module | Responsibility |
|---|---|
| `lib/cli.ts` | Parses `process.argv`, validates `--version` / `--vault` / `--out` flags, returns `ParsedArgs` union (one of: version request, error with exit code, run request with vault/output paths). |
| `lib/logger.ts` | Stderr-only structured logger with four levels (DEBUG, INFO, WARN, ERROR), emitting format `[LEVEL] message`. All non-stdout output routes here. |
| `lib/vault-walker.ts` | Recursive `.md` file discovery under `--vault` path, skips dotfiles/hidden dirs. Exports `walkVault()` for vault traversal and `countRawSources(vaultPath)` (locates sibling `raw/` directory and counts its `.md` files; returns `null` if no sibling exists). |
| `lib/frontmatter-parser.ts` | YAML frontmatter parsing (using `gray-matter`) + body-section wikilink extraction from `## Related` / `## Referenced By` H2 sections containing `[[slug\|Title]]` wikilinks. Exports `parseFrontmatter()` (returns `ParsedFrontmatter` with title, tags, status, description, body), `extractWikilinks()`, `extractFirstBodyParagraph()` (first contiguous prose block after frontmatter, excluding headings and bare-wikilink bullets, with inline Markdown stripped via `stripInlineMarkdown()` helper), and supporting utilities. |
| `lib/graph-builder.ts` | Constructs node records (id, title, tags, status, description, folder, path), extracts directional links, collapses into deduplicated undirected edges, returns page texts for embedding. `NodeRecord.description` is resolved as frontmatter value or first-body-paragraph fallback; `path` is vault-relative filepath (used for GitHub source links). |
| `lib/graph-data-writer.ts` | Serializes graph nodes/edges to `graph-data.json` with top-level `meta: { sourceCount }` object (full overwrite). Takes 4 arguments: `outputDir`, `nodes`, `edges`, `sourceCount` (number or null). |
| `lib/embeddings.ts` | `computeEmbedding()` — generates 384-dim vector via `@huggingface/transformers` and `Xenova/all-MiniLM-L6-v2` model; supports `WGE_FAKE_EMBEDDINGS=1` test seam for fast testing. |
| `lib/vector-index-writer.ts` | Serializes vector entries to `vector-index.json` (full overwrite). |
| `lib/lane-assignment.ts` | Folder→lane bucketing logic: takes visible nodes and optional hidden-nodes parameter, ranks top 4 folders by combined node count (visible + hidden), alphabetical tie-break, overflow → "Other" lane. Each `Lane` has `nodeIds` (visible pills) and `hiddenNodeIds` (revealed via "+N more" affordance). |
| `lib/second-brain-path-check.ts` | Detects hardcoded `../second-brain` path references in committed source (safety boundary). |
| `scripts/build-graph.ts` | Main entrypoint. Reads version from `package.json`, parses args, emits startup log, validates vault path, orchestrates vault walk → graph build → embedding computation → raw source counting → JSON writes, emits summary line to stdout, exits 0/1/2. |
| `scripts/check-no-second-brain-path.ts` | Runs `git ls-files` and scans for second-brain path violations; used in CI/CD. |

Key implementation details:
- Version is read at runtime from `package.json` to ensure single source of truth (no hardcoding).
- Startup log line (`[INFO] wiki-graph-explorer v<version> starting`) is emitted immediately after arg parsing and before any vault access, making it the first observable output.
- `--version` short-circuits before any startup log is emitted, so version queries remain silent on stderr (consistent with POSIX tools).
- Related/Referenced By links are sourced from Markdown body-section H2 headers (`## Related`, `## Referenced By`), not YAML frontmatter, reflecting how the real Karpathy-pattern vault stores cross-references (design-notes.md §11).
- Embeddings are computed once per page at build time; the resulting `vector-index.json` maps page IDs to their 384-dim vectors for downstream semantic search (client-side query embedding mechanism pending).

Data fetching:
- Both JSON assets are fetched client-side on page load via `Promise.all([fetch("/graph-data.json"), fetch("/vector-index.json")])`.

### Graph Exploration Components (`/graph` page)

**Layout Modes, Pane Count, and Interaction:**

- `PaneCountControl.tsx` — Icon-only toggle button (single rectangle SVG with optional vertical-line divider, `hidden xl:block`) rendered beside the hamburger, independent of `LayoutModeToggle`. Visible only on wide screens (≥1280px, `xl` breakpoint). Toggles `paneCount` state between 1 (single-pane) and 2 (dual-pane layouts side by side). Below the breakpoint, dual-pane automatically collapses to single-pane via CSS without JavaScript.
- `OptionsPanel.tsx` — Persistent icon-only hamburger button (three horizontal lines SVG, styled with `currentColor` and positioned in the top-right corner) with accessible name "Options & help" via `aria-label`, opening a dismissible panel that hosts the `LayoutModeToggle` (Swim-lane / Force-directed selector), `ThemeToggle` (Light / Dark selector), a force-directed-only "Reset view" button, and explanatory text for each affordance. Dismissible via overlay click or close button. Does not navigate.
- `LayoutModeToggle.tsx` — Selector between "force-directed" and "swim-lane" modes. Toggling switches the visible canvas via CSS `display` property in single-pane mode (both canvases stay mounted simultaneously, no refetch, no view-state loss); in dual-pane mode, tracks "last-interacted pane" so returning to single-pane shows the correct board.
- `ThemeToggle.tsx` — Light/dark switch. Updates `document.documentElement` class and persists preference to `localStorage` as `"theme": "light" | "dark"`.

**Force-Directed Graph Mode:**

- `GraphCanvas.tsx` — Wrapper around `react-force-graph-2d`; renders nodes (colored by folder taxonomy via validated categorical palette) with small status dots (active/revisiting/dormant), edges, and hover tooltips showing node title and status. Click-to-center-zoom interaction animates over ~900ms. **Container sizing:** Measures its container via `ResizeObserver` and passes explicit `width`/`height` props to `ForceGraph2D`, rather than relying on the library's own auto-sizing. The library's auto-sizing has a bug in nested/dynamic contexts: it captures container dimensions on first mount, falls back to `window.innerWidth`/`innerHeight` if the container reads as zero-sized at that moment, and never self-corrects afterward (even across many `zoomToFit` calls). In single-pane mode this was invisible (the container is rarely zero-sized for long), but broke every fresh mount of `GraphCanvas` inside `DualPaneBoard` — the canvas locked to the full viewport width, got clipped by the pane's `overflow`, and rendered nodes off-screen. The `ResizeObserver` approach sidesteps the bug entirely and applies uniformly to both single-pane and dual-pane layouts (Epic CU634Yc, design-notes.md §54). **Initial layout and re-fitting** use a "chase-fit" mechanism: `fitView()` is called repeatedly on a `FIT_CHASE_INTERVAL_MS` (300ms) interval for `FIT_CHASE_DURATION_MS` (9000ms) to track the force-directed simulation's gradual node-position settling rather than freezing on an early snapshot. This resolves the issue where a single `fitView()` call either clips later-settling nodes or produces a brief pre-fit flash. When switching back from swim-lane mode, a `layoutMode` effect re-triggers the chase-fit to recapture the correct bounds with the canvas visible (avoiding the display:none-during-fit bug). **Node focus and emphasis:** When a node is focused (via direct click or external `focusedNodeId` prop), a selection ring draws around the focused node (styled with the emphasized teal color), unrelated nodes/edges dim to 6% opacity, and directly connected edges/nodes render at full opacity in emphasized teal. **Label rendering:** Node labels are sized at a constant on-screen pixel size (`LABEL_SCREEN_SIZE_PX = 11px`, divided by `globalScale` to convert to world units) so they remain legible at any zoom level. Label visibility is gated by a per-frame collision check (`onRenderFramePre` resets `drawnLabelRectsRef`; each label is attempted in array order and skipped if its bounding box would collide with a label already drawn that frame). This collision gate has no dependency on zoom thresholds or "settled" zoom snapshots, so it can't race against the physics simulation. **Edge colors:** Theme-aware colors differentiate normal edges (25% opacity), dimmed edges (6% opacity for unconnected-to-focus edges), and emphasized edges (teal, full opacity for connected-to-focus edges) in both dark and light themes via `linkColor` prop. **Search and filtering:** Accepts `searchScores`/`relevanceThreshold` props to dim search-non-matching nodes via `ctx.globalAlpha`. Also accepts `filteredOutNodeIds` (set of node IDs to dim due to status/folder filters) and `radiusScaleByNodeId` (Map of node ID to radius scale factor for the edge-count indicator feature). **External focus control:** Accepts `focusedNodeId` (string or null) — when set by an external source (e.g., a chip click in SidePanel), a `useEffect` triggers `centerAt`/`zoom` on the target node, applying the same focus treatment a direct canvas click gets (design-notes.md §47). **Reset view:** The `onResetViewReady` callback prop hands the fit function to the parent (`app/graph/page.tsx`), allowing external controls (the "Reset view" button in `OptionsPanel`, visible only in force-directed mode) to trigger a re-fit.
  - `nodeColor.ts` — Maps folder names to colors using an 8-hue validated categorical palette (worst adjacent CVD ΔE 24.2). Folders beyond 8 slots receive a generated golden-angle HSL color to avoid color collisions. Returns theme-aware color values.
  - `StatusDot.tsx` — Maps content-freshness status (active/revisiting/dormant/unknown) to colors. Deliberately does NOT reuse the dataviz skill's reserved status palette (which means health/severity), since freshness is a different semantic concept. Reusable component for future UI expansions.

- `DualPaneBoard.tsx` — Renders both `GraphCanvas` (force-directed) and `SwimLaneCanvas` (swim-lane) simultaneously when `paneCount === 2`. Swim-lane is fixed on the left (50% width), force-directed on the right (50% width). Below the 1280px breakpoint, the component falls back to single-pane via CSS (`display: none/block` toggle) based on `layoutMode`, exactly matching the responsive behavior of the single-pane layout. Wraps click handlers to track "last-interacted pane" (which layout mode was clicked most recently) so that returning to single-pane shows the correct board (Epic CU634Yc, TOR-11-qzGSh7K).

- `FilterControls.tsx` — **Force-directed mode only.** Dropdown selectors for "Status" and "Folder" filters, with options derived live from the loaded dataset (not hardcoded). Exports `computeFilteredOutNodeIds()` pure helper function that returns a Set of node IDs not matching the current filter selections. Changes to either filter immediately pass the set to `GraphCanvas` via `filteredOutNodeIds` prop, triggering a re-render with non-matching nodes dimmed to 6% opacity. Filters are force-directed-specific; swim-lane mode does not filter (documented deferred enhancement in design-notes.md §27).

- `edgeCountIndicator.ts` — **Force-directed mode only.** Exports `computeDegrees()` (calculates each node's direct connection count within its own folder cluster) and `computeRadiusScale()` (returns Map<nodeId, radiusScale> scaling each node's visual radius between 0.5× and 1.0× relative to its folder's highest-degree peer). Used by `GraphCanvas.tsx` (passed via `radiusScaleByNodeId` prop) to visually emphasize hub nodes (larger radius) and highlight under-connected nodes (smaller radius). Helps visitors quickly spot missing links within a cluster without requiring clicks or hovers.

**Swim-Lane Layout Mode:**

- `SwimLaneCanvas.tsx` — Custom SVG/CSS-based renderer (not `react-force-graph-2d`). Displays nodes as labeled pill buttons organized into horizontal lanes (top 4 folders by count + "Other" overflow lane). Each lane renders as a tinted rounded container (e.g., `{folderColor}1a` with 10% opacity dark, `0f` light) with a folder-name heading (`<h3>` uppercase, smaller font), and a page-count descriptor ("N pages total") in a smaller, dimmed font. A minimum lane height of 84px ensures the heading, descriptor, and affordances are never clipped; remaining space is distributed proportionally by visible node count. Pill buttons display full titles with `whitespace-nowrap` (no truncation). Click-to-reveal ~950ms curved connector-line animations draw from clicked node to its edges, with folder-colored strokes, rendered via SVG at z-index -10 (behind pill text). Nodes with zero edges are permanently hidden; nodes with one or fewer edges are hidden by default and revealed with dashed borders (plus full opacity) when a connected node is clicked, or when a search match reveals them. A "+N more" affordance button appears in each lane when hidden nodes exist and the lane is not yet expanded; clicking the button reveals all hidden nodes as dashed-bordered pills, and once expanded, the affordance remains hidden for the rest of the session. Supports dark-mode-aware colors. No pan/zoom (fixed layout). Accepts `focusedNodeId` (string or null) — when an external source (e.g., a chip click in SidePanel) sets this prop during render, the component syncs its `activeNodeId` state via React's render-phase pattern, triggering the same connector-line and highlight treatment a direct pill click gets (design-notes.md §35). The focus sync is one-way and non-null-only; dismissing the panel (setting focusedNodeId to null) does not clear the board's current highlight. Memos: `zeroDegreeIds` tracks nodes with no connections (never revealed), `hiddenCandidateNodes` collects zero-degree and low-degree nodes not already on the board via click or search reveal, `expandedLaneNames` state tracks which lanes have had their "+N more" expanded.
  - `PillNode.tsx` — Rounded pill-button node renderer with `whitespace-nowrap` sizing to display full node titles without ellipsis truncation. Optional dashed border (`border-dashed`) when revealed as a low-connectivity (peripheral) node (applied by parent `SwimLaneCanvas` when setting `isRevealed` prop). Optional `isDimmed` prop reduces opacity (0.3) for search-filtered or connection-filtered nodes. Handles click events and dark-mode text color.
  - `lib/lane-assignment.ts` — Folder→lane bucketing logic: takes visible nodes and optional `hiddenNodes` parameter, ranks top 4 folders by combined node count (visible + hidden), alphabetical tie-break, overflow → "Other" lane. Each `Lane` object carries `nodeIds` (visible) and `hiddenNodeIds` (candidates for "+N more" affordance).
  - `lib/connector-line-animation.ts` — SVG curved path builder and animation duration constant (`CONNECTOR_ANIMATION_DURATION_MS = 950`). Paths anchor at pill mid-points and use stroke-dasharray/dashoffset for the line-draw effect. Distinguishes between normal connector lines (solid, 2px) and revealed-node connectors (dashed, 1.5px).

**Search, Filters, and Data Display:**

- `ExplainerSection.tsx` — Static "why build this" explainer section (HTML rendered below the graph, reachable via page scroll). Includes a "second-brain/dynamic context" value proposition, explanation of how graph visualization surfaces missing links (via the edge-count indicator), and a "Try it yourself" walkthrough explicitly naming the **force-directed mode** (via Options & help) and tying together filters, edge-count indicator, side panel, and semantic search to demonstrate link-discovery workflow. Scrollable page layout (outer container wraps both the fixed-height graph section and this scrollable explainer) allows the explainer to exist alongside a fixed-height graph canvas without breaking auto-sizing.

- `SearchInput.tsx` — Controlled search box with live query input. Displays "No closely matching results found" when a query has no results above the relevance threshold. Wired to `useSearchRanking` hook. Displays live match count. Ctrl+K and `/` global focus shortcuts activate the search input from anywhere.
- `useSearchRanking.ts` — React hook that debounces user input (250ms), performs client-side query embedding via dynamic import, scores every page by cosine similarity against its precomputed embedding (via `lib/query-embedding.ts`), and returns scores and UI flags (isSearchActive, hasResults, matchCount). Exports `computeSearchDimmedNodeIds()` and `computeMatchCount()` — pure functions that both `GraphCanvas` and `SwimLaneCanvas` consume to ensure identical search filtering behavior across layout modes. Reuses the same `Xenova/all-MiniLM-L6-v2` model (384-dim) settled by build-time embeddings, guaranteeing embedding-space parity. Scores are passed to both canvases; each canvas dims non-matching nodes identically.
- `Legend.tsx` — Reusable legend component displaying folder taxonomy and content-freshness status indicators. Consumed by `SidePanel.tsx`'s onboarding card to help visitors understand the graph's folder colors and status-dot meanings at a glance without requiring interaction.

- `SidePanel.tsx` — Responsive side panel. **Desktop layout (`md:` and above):** Rendered as a flex column in the right sidebar, always visible. **Mobile layout (below `md:`):** Hidden by default, appears as a `position: fixed` bottom-sheet overlay (max-height: 70vh, `overflow-y: auto`) anchored to the bottom when a node is selected. When no node is selected, both layouts display a "Start anywhere" onboarding card: a title, a built-from line (e.g., "This map is built from 47 interlinked wiki pages across 5 folders"), a folder legend and status legend (both managed by `Legend.tsx`), and a suggestion line ("Try clicking a brightly-colored, well-connected node, or search for a topic above."). When a node is clicked, both layouts display the node's title, tags, content-freshness status dot, a folder badge (colored via `getFolderColor()` to match the node's graph color), the node's description (frontmatter `description:` field or first paragraph fallback, empty string if neither), and a "Connected pages" section listing directly connected related nodes as clickable `PillNode` chips grouped by folder (via exported `groupNodesByFolder()` helper). Clicking a chip re-targets the panel to that node, driving the same focus treatment a direct graph click gets: canvas center/zoom in force-directed mode or active-node highlight/connector-lines in swim-lane mode (via `focusedNodeId` prop). The helper `getRelatedNodeIds()` defensively handles both string ids and d3-force-mutated node-object references. Includes a "View source on GitHub" link (built from hardcoded repo/branch/vault constants) that lets visitors verify page content is genuine and source-traced. Close button reverts the panel to the onboarding card state (desktop) or dismisses the overlay (mobile). See design-notes.md §21 for responsive layout rationale.
- `EmptyState.tsx` — Renders a dedicated message when the graph contains zero nodes (e.g., empty vault).
- `ErrorState.tsx` — Renders error message naming the problem and next action when JSON fetch fails.

### Shell and Theme Architecture

- **Geist typeface:** The Geist font is loaded via `next/font` and bound to `--font-sans` CSS variable. Previously, a hardcoded `font-family: Arial, Helvetica, sans-serif;` rule in `body` was silently overriding the font binding; this rule was removed, so Geist now renders correctly throughout the site.
- **Accent color system:** A shared `--accent` CSS custom property (defined in `:root` and `.dark` in `app/globals.css`) mirrors the `ACCENT_LIGHT` and `ACCENT_DARK` values exported by `components/graph/nodeColor.ts` (palette slot 0, a blue from the validated categorical folder-color palette). This connection ensures the header logo, CTA button, and focus ring all use the same folder-color-derived accent instead of an unrelated stock Tailwind color, making the interface visually coherent with the data it displays. The CSS variable approach enables static/server components (like the home page) to use the accent without threading an `isDark` prop.
- **Focus ring with protected visibility:** A global `:focus-visible` rule applies a 2px solid outline in the accent color with `outline-offset: -2px`. The negative offset draws the ring inside the element's own box rather than outside it, ensuring keyboard-focused elements inside ancestor containers with `overflow-hidden` (like the swim-lane board's lane containers) still show a visible ring instead of having it clipped.
- **Dark-theme-by-default:** `app/layout.tsx` sets `dark` class on the `<html>` root element by default, with `suppressHydrationWarning` to avoid hydration mismatch during theme restoration.
- **Anti-flash script:** An inline script in `<head>` runs before paint, reading `localStorage.getItem("theme")` and removing the `dark` class if a stored "light" preference exists. This prevents a flash of dark theme on page load for users with a light preference saved from a prior session.
- **Dynamic theme updates:** When the user toggles the theme, the UI updates `document.documentElement.classList.toggle("dark")` and persists the choice to localStorage.

### Design Notes

- `react-force-graph-2d` touches canvas and window APIs at module scope, which breaks Next.js's build-time static-export prerender pass. The dynamic import with `ssr: false` ensures the library code never runs at build time, keeping the prerender pass clean even inside a `"use client"` file.
- Semantic search (live query embedding and cosine-similarity scoring) is implemented as of Epic TBZJM0j. Client-side query embedding delegates to the existing `computeEmbedding()` function via dynamic import, reusing the same model and configuration as build-time embeddings to guarantee embedding-space parity. See design-notes.md §19 for the resolution of this previously-open design question.
- Swim-lane and force-directed canvases are both mounted simultaneously and toggled via CSS `display` property. This preserves pan/zoom state and avoids expensive refetches when switching modes (design-notes.md §20).
- Side panel is responsive: desktop sidebar (always-visible flex column), mobile bottom-sheet overlay (appears on node selection). See design-notes.md §21 for responsive layout rationale and constraints.

**Build pipeline (triggered on push to `master`)**:
1. Checkout code (this repo: `wiki-graph-explorer`)
2. Checkout external public vault (secondary `actions/checkout@v4` step fetches `athandapani/ai-adoption-wiki` repo at `path: ../ai-adoption-wiki`)
3. Install Node.js 20 + npm dependencies
4. Run `npm run check:vault-safety` — scans git-tracked files for hardcoded `../second-brain` path references; exits 1 if found
5. Run `npm run build:graph -- --vault ../ai-adoption-wiki/wiki --out public` — parses external vault, generates `graph-data.json` and `vector-index.json`, writes to `public/` directory
6. Run `npm run build` — Next.js static export; reads JSON assets from `public/`, emits static HTML/CSS/JS to `out/`
7. Upload `out/` to GitHub Pages artifact
8. Deploy artifact to GitHub Pages (requires manual one-time repo settings enablement: Settings → Pages → Source: GitHub Actions)

**Key constraints:**
- Vault path is hardcoded in workflow (`../ai-adoption-wiki/wiki`) with no override mechanism — prevents accidental deployment of private vault content. The workflow uses a secondary `actions/checkout@v4` step to fetch the external vault at a sibling path before the build step, allowing a single literal `--vault` argument to reference it.
- Output directory is hardcoded as `public` — becomes the fetch root for client-side JSON asset requests.
- No container runtime in production; deployed artifact is pure static files.
- In-repo `public-vault/` 2-page placeholder was retired in epic iv5GPN9 — all builds now target the external vault only.
